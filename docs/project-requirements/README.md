## 1. 整体目标

建设以 ThingsBoard 为业务与后端基础、以 Vue Vben Admin 为前端基础的物联网管理平台。前端使用当前 Vue 3、TypeScript、antdv-next 与 Vben 组件体系，统一 shadcn/ui 风格，逐步补齐管理、配置、详情、实时数据和规则编辑能力。（S19、S20、S22）

核心原则：

1. **业务看原版，页面看本项目。** 接口、字段、权限、默认值和交互流程核对 `F:\workspace\thingsboard\ui-ngx` 及 Java 后端；代码组织和视觉以当前项目确认过的页面为基准。
2. **同类页面保持一致。** 列表和普通表单主要参考 `tenant/list.vue`、`tenant/form.vue`；实体详情参考设备详情与公共 `detail-page`。
3. **优先复用现有组件。** 优先 Vben、adapter 和已经建立的业务公共组件；Vben 不满足多选、远程搜索、上传、分步等功能时使用 antdv-next。
4. **结构清楚，代码直接。** 不堆积没有实际用途的文件、包装函数、状态、类型和抽象；明确的数据处理直接写清楚。
5. **完整保留真实业务。** “简洁”不意味着删掉权限、必要表单校验、后端协议或提交失败处理。
6. **整理后的规范是有边界的。** 单次页面要求不能自动扩大为所有模块的永久规则；讨论、评估与方案不能自动视为实施授权。

## 2. 平台与基础能力

### 认证、权限与请求

- 迁移登录、请求适配和租户页面，使用 ThingsBoard 实际认证与业务接口。（S20）
- 区分系统管理员 `SYS_ADMIN`、租户管理员 `TENANT_ADMIN`、客户用户 `CUSTOMER_USER`。
- 路由、菜单、列、操作按钮和详情页签都要结合角色配置；不能只隐藏按钮而请求越权接口。
- HTTP 适配沿用本项目的 JWT、刷新令牌、错误处理和裸 JSON 响应契约；WS 复用有效令牌获取与会话过期处理。具体实现以当前请求层为准。（S68）
- 系统参数由全局 store 统一请求和复用，不能因计算字段、告警规则等调用方不同而重复建立接口或专属命名。（S62）

### 通用表格

- 从 VXE 迁移到基于 JeeSite Table API 的 `BasicTable/useTable`，只引入需要的表格能力，不引入 JeeSite Form、字典和整套业务组件。（S12、S19、S20）
- 公共表格位于 `packages/effects/table`；ThingsBoard 的分页、排序、筛选和默认外观在 `apps/web-ui/src/adapter/table.ts` 配置。
- 支持列显隐、列顺序、固定左右、列宽、密度、选择、多选批量操作、刷新、空状态、嵌入模式与自适应高度；早期还提出列设置持久化等扩展目标，不能仅因存在配置项就判为已验收。
- 早期选定的迁移范围为 C1–C10、C12、U1–U12、S1/S4/S6/S7、D1–D12、A8；后续要求优先对齐外观、API 与常用交互。高级树表、行内编辑等未因此成为当前必须补齐的功能。（S12、S19）
- 操作列最终使用 `actionColumn` 包含 `actionProps`，内部对接 Vben 操作组件；默认固定右侧。（S39/19–37）

### 实时数据

- 全局 WS 设计应兼容属性、遥测、通知、API 使用量和未来仪表板的订阅，不按页面分别建立连接。（S68/2–15）
- 采用 `@vueuse/core` 的 `useWebSocket`，连接与订阅放 store，组件通过 `hooks/use-ws.ts` 使用；早期 `api/ws.ts` 与 `composables/use-ws.ts` 方案已被后续要求替代。（S68/20、27、42–43）
- 协议类型参考 ui-ngx 的 telemetry models；订阅随实体、条件、页面生命周期变化更新与清理；令牌使用 `getValidAccessToken`，会话失效衔接 `expireSession`。
- HTTP 与 WS 的适用范围按业务场景区分，不把所有页面强制改为实时订阅。usage 当前明确要求以 HTTP Entity Query 为主要接口。（S73/1）

### 设备、资产、实体视图

- 设备创建两步：设备详情、设备凭证。凭证类型以分段控件切换，成功后显示“设备已创建，检查连接”流程；分步条固定，内容独立滚动。
- 列表有设备配置与在线状态表头筛选、网关标识；在线用主题色，离线用异常色。客户列及管理操作按角色显示。
- 设备支持 Excel 导入、批量分配与批量删除；资产也要求导入和批量分配。实体视图没有在对应需求中要求照搬设备导入。
- 设备、资产、实体视图的管理操作按业务判断分配/取消、公开/私有；客户用户不显示这些管理操作。
- 实体视图目标实体选择为“实体类型＋实体”同行；属性传播和时序配置采用可折叠 FormSection。实体名称通过 Entity Query 获取并可跳转。
- 实体视图的属性传播说明必须体现：保存或更新视图时复制指定属性，并非目标属性每次变化就自动传播；自动传播需相应规则链逻辑。（S39/49）

### 属性、遥测、关系与事件

- 属性区分客户端、服务端、共享属性。属性页不分页，执行过滤/排序；以单个 `datasource` 为核心，HTTP 与 WS 按 scope 获取。（S68）
- 属性与遥测保留独立列表，最后决定复用属性/遥测值编辑表单；不维护冗余历史快照，原始记录为 `record`，编辑值由表单管理。
- key/value 支持复制，统一“复制”“已复制到剪贴板”；显示值类型；布尔输入旁有 true/false。
- 遥测刷新复用表格顶部刷新入口。
- 关系表单实体类型与实体选择同行；编辑只改附加信息；实体名可跳转，关系类型可复制；候选实体优先 ApiSelect/Entity Query。
- 事件为实体详情内嵌列表，接收实体 ID 和允许筛选的事件类型；调试页不另建重复事件体系。
- 早期“所有列表不能前端过滤”针对服务端分页列表；属性页的本地过滤是明确例外。

### 计算字段与告警规则

- 计算字段实现全部业务类型，类型顺序简单计算靠前、实体聚合靠后，名称、label、help 和 ui-ngx 对齐。
- `form.vue` 负责入口和统一提交；公共配置放外层；不同类型放 `configurations` 并管理自己的数据与必要子组件；避免通用字段工厂和多余中转组件。
- 参数、地理围栏区域组、传播数据、聚合指标使用表格；无参数时给出简洁空提示；参数名支持复制。
- 共享 `field-arguments` 不出现计算字段/告警规则专属命名；取消无用途的 `nameMode`；props 接收、emit 回传，不直接修改 props。
- 告警规则顶层统一收集参数、触发条件、清除条件、传播等配置并校验；条件、参数过滤器、复合过滤器、调度通过分层弹窗编辑。
- 顶层触发条件展示严重程度、告警条件摘要、告警调度摘要、附加信息、移动端仪表板；移动端仪表板直接 Select。
- 调试配置与名称/告警类型同行；通用调试按钮最终在 `components/widget/debug-settings-button.vue`，内部取 systemStore 参数。
- 列表最终以“事件跳转＋调试配置”替代旧 `debug-event.vue` 弹窗入口；应用调试配置时提交后端。（S70/44–60）
- 告警列表操作最终要求详情、删除；详情弹窗参考 ui-ngx；默认查询所有时间。不要把确认、清除继续作为该列表的默认操作。（S70/63–65）

### 代码编辑器与脚本测试

- Monaco 基础 CodeEditor、ScriptEditor 与 TBEL/JavaScript 支持优先用于计算字段、告警规则、规则链/节点、设备配置和属性；部件开发等曾明确列入后续接入范围。（S47、S50）
- 懒加载、本地 Worker、自适应弹窗尺寸、关闭释放 editor/model；部件多标签场景保留 model、撤销记录和光标。
- 支持高亮、参数补全、格式化、只读、title/插槽；全屏仅铺满浏览器页面。
- 测试调用真实后端脚本测试接口；测试、格式化、全屏用图标和 VbenTooltip，语言在测试左侧。
- 测试弹窗左侧脚本，右上参数表格、右下输出；测试/取消/保存位于底部；错误用现成 alert 弹窗，不再包一层 ErrorModal。
- JSON 只读展示曾明确要求复用 JsonViewer；当前代码另有 json-editor，编辑与只读展示必须按用途区分，不能以历史一句话直接删除现存编辑器。

### 系统设置、通知、OAuth2、移动中心

- 设置采用左侧菜单、右侧内容；标题固定顶部、操作固定底部，中间滚动；统一 FormSection 与 VbenForm。队列、AI 模型是表格页，保留相应高度布局。
- 队列表单与租户配置有相似业务，但用户明确要求独立实现，不能强制共用整张表单。（S32/28）
